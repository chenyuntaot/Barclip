# 一期：菜单栏文本剪贴板历史

## 实现状态（2026-09-16）

代码实现完成，Xcode Debug / Release Build 与 16 项测试通过；真实菜单栏点击验收仍待手动完成，不能视为全量验收完成。

需求范围：macOS 原生、菜单栏常驻、Dock 不展示、仅文本历史、一键清空、容量设置，以及设置页中的两种保存策略。

## 功能行为

| 功能 | 当前行为 |
| --- | --- |
| 历史采集 | 启动后每 500ms 检查新复制的文本，不导入启动前的当前剪贴板 |
| 排序与去重 | 新文本置顶，完全相同文本再次复制时移到顶部 |
| 文本保真 | 保留原始空格、换行和 Unicode；空白文本忽略 |
| 点击记录 | 写回系统剪贴板，显示已复制提示，由用户在目标应用粘贴 |
| 一键清空 | 清除内存及已保存的历史，不清除系统当前剪贴板，不自动重新收录当前值 |
| 容量 | 10、25、50、100、200，默认 50；调小立即移除最旧记录 |
| 退出后清空 | 默认模式，仅在当前进程保留；切换到此模式立即删除磁盘缓存 |
| 重启后保留 | 将当前及后续历史保存到本机，启动时恢复 |
| 设置 | 菜单栏面板内切换设置/历史页，设置选择跨重启保留 |
| 退出 | 停止监听并等待最新缓存操作；失败时可返回重试 |

实现文件和技术选择见 [architecture.md](architecture.md)。

## 待手动验收

1. 正常启动应用，检查菜单栏图标可见且 Dock 无图标。
2. 从文本编辑器复制中文、多行、Emoji，打开菜单验证内容；点击旧记录，在编辑器粘贴验证原文。
3. 关闭面板后继续复制，重新打开确认监听仍在工作。
4. 设置容量 10 条，复制超过 10 条不同文本，确认保留最新 10 条。
5. 选择重启后保留，退出并重新打开，确认历史与设置恢复。
6. 切换退出后清空，确认当前记录仍可用，退出重开后为空。
7. 清空后关闭再打开面板，确认历史不回填；重复清空、返回设置正常。
8. 在支持剪贴板访问控制的系统上拒绝/恢复权限，验证提示和恢复。
9. 检查真实浅色/深色环境、小屏幕、键盘导航和 VoiceOver。

## 已知限制与后续方向

- 500ms 内连续复制可能丢失中间值；只捕获文本，不含图片或文件。
- 单条文本上限 1 MiB；不包含搜索、收藏、全局快捷键、开机启动、云同步和自动粘贴。
- 持久化为本机 JSON，未加密；强制结束进程或断电可能丢失尚未写入的最新变更。
- 已验证当前 Mac；macOS 14/15 的真实系统权限与界面行为仍需对应系统验收。
- 当前构建用于本机开发，未进行分发签名、公证或安装包发布。
- 如后续扩展媒体、大数据量、索引或更高频采集，应单独评估存储和监听方案。

## 2026-09-16：修复有数量但看不到历史记录

- 修改：为列表设置 180 点最小高度、280 点理想高度、320 点最大高度；仍然支持滚动，不改动历史数据和采集逻辑。
- 回归：新增 `testHistoryRemainsVisibleUnderCompactMenuProposal`，使用真实 ClipboardMenuView 和 3 条模拟数据，在 NSHostingController 最小高度提议下测量。修复前面板只有 151.08 点，断言失败；修复后通过。额外渲染该紧凑布局，检查三条记录可见。
- 全部 16 项测试通过。原先只验证理想尺寸的快照，未覆盖菜单栏最小尺寸协商，这是之前漏检的原因。
- 真正运行中的旧应用不会热更新，需退出后重新打开新构建。会话模式退出会清空历史；需要保留时可先在设置选择“重启后保留”。
